This preserves useful local c2 results after an unresolved driver miss: finish the independent short scenario if health remains valid. It does not label the miss GAME or TEST by guessing.

### D5 — verdict words: MERGE to five statuses plus fixed reasons/ownership

I concede my seven headline terms are more than the user needs. Claude's short vocabulary is easier to read. I retain the distinctions R15 requires, the no-bare-whole-game-PASS rule, and visible earlier findings after a later error. Claude's blanket 'not counted' can discard a valid earlier game observation when an unrelated later player/health failure occurs; c2's missing-player SCRIPT ERRORs illustrate why evidence validity needs timestamps (`trial_c2.md` S4).

> **D5:** One host reducer prints one RESULT with exactly one status: PASS, FAIL, INCOMPLETE, TEST, or NOT HEALTHY. Priority is TEST > NOT HEALTHY > FAIL > INCOMPLETE > PASS. TEST means invalid required observation, malformed plan/event, failed required output, or demonstrated test input failure; it does not declare all game code innocent. NOT HEALTHY means frozen/stopped physics, unallowed pause or missing required actor. FAIL means a valid required contract/check failed; attach owner=GAME only when valid prerequisites and the measured game-contract violation establish it, otherwise owner=UNRESOLVED. INCOMPLETE means mandatory work/window/reach receipts are absent, including an unresolved missed flat-out attempt. PASS requires valid health, every mandatory scenario and work item complete, every required observation window valid and complete, and no required failure. Exit codes: PASS=0, FAIL=1, INCOMPLETE=2, TEST=3, NOT HEALTHY=4. STALLED and KILL FAILED are reasons, not sixth/seventh statuses. A deadline expiry is INCOMPLETE/STALLED with owner=UNRESOLVED unless another measured condition gives the higher status. NOT REACHED is a per-rule healthy-absent-trigger line; mandatory absence also causes INCOMPLETE. NOT PROVEN identifies claims outside scope. Print all secondary conditions and earlier valid findings with times; evidence invalidated by the same cause is marked invalid. Never erase a valid earlier finding merely to select the headline. Append the named scope even on PASS.

Priority is a proposed fixed presentation convention, not a measured causal ordering. A nonzero combined verdict alone does not earn S2: the referee still scores caught AND correctly named from its evidence.

## One-hour build: what fits, what does not, and cuts

I think a minimal integration is plausible; no combined build has been timed. **Cut first:** full recorder/default multi-phase telemetry and all causal pair tooling (D4 already cuts these); invented upper ground bands; a new ring buffer; path-based script-error ownership and its two special controls; generic mesh attachment extensions without verified centres; full-suite await instrumentation; new planner/driver/controller or broad prop sweep. **Cannot be cut while claiming the combined method qualified:** actual C2 dependency validation/T4, all-direction hub repair and its negative, N5 bounded live-step control with exit verified, mandatory semantic work/window receipts, non-substitution aggregation, fixed verdicts/scope, unchanged game, retained failure evidence. Failure to fit these means failed/partial qualification. Neither a clean local-state line nor inherited health scores rescues that.

**Unresolved work that an hour cannot honestly guarantee:** reliable whole-route driving across 61–68; a new final departure witness with agreed numeric limits; proof of two-player hut completion between scripted placements; an unseen whole-puzzle actor; automated causal diagnosis. D2 permits the smallest spread experiment, not a promise of reliability. D6 requires the departure specification before claiming it.
