## Blocking false-PASS paths

### 1. A requested lane can disappear and the combined command returns success

**Static defect, verified in `diff:tools/method_run.sh`, fast split/aggregation block.** `.last_fast` and `.last_1x` start as `-`; `worst=0`. A part still marked `-` is skipped. Subprocess exit statuses go through `sed` pipelines, and the aggregator relies on verdict paths rather than requiring one result for each requested part.

Concrete path: the fast lane succeeds, but spring is refused by the two-game guard before it creates its output folder. `.last_1x` remains `-`; the aggregate consumes only fast's PASS and returns 0 despite missing spring. If both parts refuse, nothing changes `worst=0`. This is distinct from the recorded final run, where both results exist. Shared `.last_*` files also allow another invocation to reset/replace the evidence pointer.

**Required:** invocation-local returned run IDs, explicit expected-part inventory, refusal/missing/truncated verdict is non-PASS, propagate launch failures, validate exact requested scenario coverage. Test missing first part, missing second part, both refused and concurrent invocations. No live reproduction was performed in this audit.

### 2. A step can close late between watcher polls without being judged

**Static defect, verified in `diff:tools/method/method_watch.py`, CLOSE and deadlines blocks.** CLOSE pops the OPEN, computes duration for reporting, and never compares that duration with its budget. Only entries still in `opens` after draining the event batch face the STALL check.

A step can cross its game deadline and close before the next poll, or both OPEN and late CLOSE can arrive in one read. The step is gone before judgement. At fast speed a poll covers more game time, so this can admit a late fast completion which would be caught while open at 1x. Even the existing 15-versus-10 control could escape if the watcher were delayed sufficiently. No completed over-budget entry appeared in the archived traces' `opens_max`; this is an uncovered negative case, not a claim that those runs did overrun.

**Required:** judge completed intervals using their stamped game AND wall durations before removing them, preserve a non-PASS even when the evidence arrives after closure/at shutdown, and verify all final events are drained. Add just-over-budget closed-step and delayed-reader controls at both speeds, plus an on-time clean pair. The current long-open control is necessary but insufficient.

### 3. Proof identity is printed, not enforced

**Static gap, verified in `diff:tools/method/prove_ghat.py` and `method_watch.py`.** Early stop still uses `x in h`; PROVED still uses substrings in FAIL lines. Folder selection is still before/after glob plus fixture-name substring, choosing the last match. It is narrower than the old global latest-folder choice but does not bind lane, invocation, exact fixture set, source or exact expected check IDs. Two same-group invocations can still compete. A generic H1 line is not a substitute for every plant's own expected check.

The demonstrated heat and jug groups did record all their expected named failures before stopping: that part is right. General safety does not follow merely from those successful examples.

**Required:** exact scenario/check or rule IDs and invocation/fixture identity in the acceptance decision, process-exit verification and a sealed verdict before PROVED, no glob inference. Test one expected failure missing, a similarly named wrong check, wrong-run evidence, and a batched member whose own check is absent. Until implemented, disable automated early proof acceptance or have independently checked exact receipts; never count a generic group FAIL as all plants proved.
