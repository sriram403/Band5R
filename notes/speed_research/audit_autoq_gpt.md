## Required changes

1. **Bind actual inputs and run modes.** Validate the canonical full walk, setup and all non-step execution fields, not just tree hashes. SAME requires the identical walk; suffix differences explicitly select REPAIR even when k is unchanged. Preserve schema/profile/point/receipt binding. Reject ambiguous duplicate step/watch names or bind dependencies only to preceding definitions. Keep generators untouched by repair; current `test` includes generators (`tree_id.py:109?114`).
2. **Split repair status from comparable execution.** Retain layer 3/next_step only where their reference actions are unchanged throughout their observation window. For short k, require the subsequent sampled actions unchanged or mark trajectory comparison inapplicable with a reason; never manufacture SAME. Apply this policy in both live `gate_step` and offline `judge_resume` (`live.py:321?345`).
3. **Define structured outcomes.** Persist a per-run completion record: terminal status, execution step index, failure source/check ID, and diagnostic payload. Missing/truncated/crashed runs cannot qualify; exclude gate/restore/client-abort failures. Compare ordered suffix step/check outcomes as well as the terminal result, with explicit normalization of measured diagnostics. Retain layer checks; outcome agreement cannot prove unobserved state equal (**I think**). Preserve raw logs.
4. **Bound the lifecycle.** Explicit qualification-child mode disables the post-run hook and every last_fail mutation, including deletion. Autoq runs only for the just-completed scripted failure, after stopping its game; freeze inputs, carry lane/profile, and use `NO_MAKE=1`. Persist at most two attempts per producer/point/identity; only explicit `--again` retries a stopped attempt. Commit metadata atomically without overwriting a newer run. No fallback after a live gate failure.
5. **Make fallback one decision.** Share preflight logic between `--gate-check` and execution; revalidate changed inputs. Default use requires valid bound receipts, never merely `qualified:true`. Preserve explicit refusal. Store `step` as its name plus a separate numeric index: spec:29's numeric step conflicts with `live.py:92?99`. Resumed failures reuse only their original fresh source; they never become producers.
6. **Make point selection reference-aware.** Reject missing/malformed references, early-failed +3 s references, invalid indices and nonfresh producers offline; record why each candidate was skipped. An admissible point remains unqualified until both full checks pass.
7. **Keep wide checks independent and honest.** Use full immutable walk plus a runtime stop-after limit, a diagnostic receipt distinct from SAME/outcome, and no last_fail/autoq effects. Compare node presence, stable identities, script fields and relevant unscripted descendants/engine state; list remaining autoload/static/resource blind spots. Show unknown differences; allow only justified field-specific normalization, never auto-mask from one restore. Measure capture ms/bytes and clock effects. Report possible fixes as hypotheses.
8. **Freeze a falsifiable proof matrix.** Add planted controls for: suffix-only repair selection; protected prefix/setup/dependency changes; short-k sample spill; restore-only failure and changed intermediate checks with the same terminal FAIL; diagnostic-only text variation; missing terminal evidence; recursive hook/attempt cap; stale or successful last_fail mutations; default fresh versus explicit refusal; and wide-only new-node/unscripted-state loss plus missing wide artifacts. Each must fail with its guard disabled. Correct the budget, suppress producer autoq during staged controls, and run the wide pair before changing identity or account for another producer. A content edit is required: merely touching mtime does not change a content hash (`tree_id.py:61?76,107?114`).

**Class-wide fix:** separate immutable run evidence, qualification orchestration, repair admission and diagnostic probes; give each an explicit mode and terminal record. Reusing a boolean REPAIR flag, process exit 1 or mutable last_fail as all four contracts creates the holes above.
