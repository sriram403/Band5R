## Findings

| B1 | **Qualification evidence is not fully bound or validated at consumption.** `receipts` checks point bytes, gate/protocol/profile and four code hashes, but does not check the receipt run's walk, terminal record, source point, schema, run/PID against run.json, or SAME's complete layer results. It trusts the stored verdict. A record with missing terminal/walk evidence can therefore qualify the default start. This is a fail-closed contract hole, not evidence that the actual saved pair is false. | `tools/method/walkgate.py:887-925`; `default_start:1016-1022`. Reproduced read-only using the controls' own fixture: `qualified(appdata/autoqctl/work/points, 'ghat_P/13', 13, producer_identity)` returns `[]`, although `r_1/walk.json` and `r_1/end.json` do not exist (same for r_2). The controls deliberately manufacture these incomplete receipts: `autoq_controls.py:60-71,169-172`. |
| B1a | **REPAIR still permits generator/test input code edits.** The prior audit explicitly required generators protected. All `tools/live/` files, including `make_*.py`, remain in `test`, and REPAIR ignores that hash. A suffix edit plus a generator edit passes the protected-code comparison. | `tools/method/tree_id.py:109-114`; `walkgate.py:861-881`. Read-only experiment: keep qualification valid, change only identity.test and step 14.max against F's walk; `repair_check` returns `[]`. This demonstrates the missing comparison, not a live experiment. |
| B1b | **Malformed structured end evidence can pass.** `outcome({'status':'DONE'}, {'status':'DONE'},13)` returns `[]`: required index/kind/check/outcomes fields are absent. Non-list or invalid outcome entries are silently filtered instead of rejected. | `walkgate.py:768-790`; direct offline reproduction above. Generated complete records in this proof are valid; the missing guard matters to the promised missing/truncated-evidence policy. |
| B2 | **Attempt cap is not durable during execution; newer state is not protected atomically.** The attempt is first persisted after all child runs finish. Killing autoq during a child leaves no in-progress attempt marker, so an ordinary retry can launch again without `--again`; concurrent invocations can both launch. `finish` checks ownership, then separately replaces last_fail; a newer failure or successful deletion between those operations is overwritten/recreated. Whole-book read/modify/write also loses concurrent entries. | `autoq.py:124-129,149-190` (no attempt reservation before Popen at 167); `autoq.py:55-71` and `jwrite:36-41`. These are code-path deductions, not live race reproductions. Atomic replacement prevents partial JSON; it does not make the ownership check atomic. |
| F3 | **The backstop can declare STALLED with a healthy result already available.** Timeout is tested before reading res.json. If the client is descheduled/suspended for >30 s after seeing the end line, it returns 2 without checking the matching response. It is not a false-SAME path, but can discard a healthy finished run. | `tools/live.py:248-254,261-278`. The normal end marker really follows gameplay and failure screenshot, so ordinary ongoing step execution cannot itself trigger this timer: `LiveControl.gd:940-960`. |
| F4 | **Windows retry fixes a plausible and specifically exercisable failure, but scope/cost needs care.** Files are closed before rename; retry attempts every 10 ms, bounded to about 2 s of sleeps. `_replace` is synchronous on the game thread and used for heartbeat and every evidence write, not only the final response. Every lock can therefore pause simulation and advance wall ages. On exhaustion it logs an error but returns no failure to the caller. | `LiveControl.gd:165-179,579-591`; bench holds res.json open for 1 s before reading the answer: `tools/method/race_bench.py:57-76`. The bench tests final command responses, not locked heartbeat/evidence writes or timeout propagation. |
| F5 | **Proof/control coverage is narrower than 'all 8 taken' suggests.** Seven mutation controls are real, but no child is launched in lifecycle tests, and they do not exercise interruption/reservation, recursive shell hook, newer successful last_fail ownership, or wide-only missing-node/unscripted-state/missing-artifact guards. | `autoq_controls.py:189-213,218-231`. A second walk, live needs-binding and the LIVE_GROUPS suggestion are openly unproved: `autoq_result.md:48-58`. |

**Class fix for B1/B1a/B1b:** establish one validated evidence contract used by qualification and default admission: bind the full immutable walk, protected generator/test code, exact source/run/process/mode and complete end record; bind artifact digests or rejudge the underlying records. Reject malformed evidence. Do not rely on a verdict string plus a partial identity tuple. This is not a demand to distrust every valid historical receipt or rerun the whole game.

**Class fix for B2:** reserve and append each attempt durably before launching, under a per-lane/walk lock shared with last_fail writers. Serialize ownership-checked finalization and preserve interrupted attempts. `--again` should append an explicit attempt, not overwrite its history.
